# Helper security and installation

Aervane keeps AppleSMC writes in a separate LaunchDaemon. The application connects to the daemon over the Mach service `dev.kirniy.aervane.helper`. Both peers require an Apple-trusted signature, their expected bundle identifier, and the same certificate team as their own signature. The helper exposes only snapshot, percentage, automatic-restore, and heartbeat methods; callers cannot provide raw SMC keys or journal paths.

The app registers its embedded `dev.kirniy.aervane.helper.plist` with `SMAppService.daemon(plistName:)`. macOS controls approval in Login Items & Extensions. The app reports service errors/approval requirements instead of copying files into `/Library/LaunchDaemons`, and has no `SMJobBless` fallback. Public distribution is intended to use Developer ID signing and notarization. The local development identity is not a substitute for that release workflow. Installation has not yet been validated on the development Mac.

Only fan index 0 is implemented. The target is a percentage of the firmware maximum, clamped to the minimum, with exact SMC payload/type checks. A request is rejected outside 0–100%, on unavailable or invalid temperature data, or at the critical threshold. The helper verifies manual mode and target readback before reporting success. `0%` cannot stop hardware whose reported minimum is nonzero; the UI shows the floor.

Each authenticated XPC connection has a unique session. Only one session can own control; other sessions cannot renew its lease, restore its fan or replace its journal. The owner sends heartbeats every five seconds; expiry after fifteen seconds, disconnection, temperature faults or control errors initiate automatic restoration. Ownership remains pending until automatic mode is confirmed, and failed restoration is retried. These paths are covered by injected-driver tests, not physical fault tests yet.

Before writing, the helper records its owned previous/intended target and operation phase in `/var/db/dev.kirniy.aervane/lease.json`. The fixed directory/file require root ownership and permissions 0700/0600. After a crash, launchd restarts the helper. Startup recovery compares a fan-only readback with the valid journal before adopting the previous lease and restoring Auto. It retries transient read failures without requiring a client connection, and discards obsolete journal targets instead of taking over unrelated manual settings. Temperature availability is not required to restore Auto.

The journal reduces the crash window but is not proof of safety on every machine. Multiple external controllers must not manage the fan concurrently. Actual installation, write/readback, process-kill and watchdog recovery remain release gates in [verification.md](verification.md).
